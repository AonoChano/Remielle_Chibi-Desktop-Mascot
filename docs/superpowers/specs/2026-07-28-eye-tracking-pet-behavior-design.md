# 眼神鼠标追踪与桌宠动画行为设计

## 目标

为 Electron 桌宠加入默认开启、可持久化的全屏眼神鼠标追踪，并用可测试的独立状态机实现双击随机动画、循环计数、拿笔计时和竞争优先级。控制面板中的“主面板”改名为“桌宠”，眼神追踪开关直接安插在内容背景上，不增加卡片底色。

## 已确认规则

- IDLE 每完成 10 个循环抽卡一次，以 15% 概率进入“画完欣赏”。
- 拿笔状态每累计 10 秒抽卡：思考 45%、委屈 25%、不触发 30%。
- 所有瞬态动作期间忽略双击，当前动作链不可被截断。
- 眼神追踪默认开启、全屏生效、设置持久化；关闭后平滑回正。
- 疯狂绘画后的 `d_win` 是一次非循环收笔动画。
- 动画测试模式暂停自动状态机并独占动画播放；退出测试模式时回到 IDLE。

## 动画映射

| 语义 | Spine 动画 | 播放方式 |
|---|---|---|
| IDLE | `a` | 循环 |
| 拿起画笔 | `a_win` | 循环 |
| 思考 | `b` | 循环指定轮数 |
| 画完欣赏 | `c` | 循环指定轮数 |
| 疯狂画画 | `d` | 循环指定轮数 |
| 画完收笔 | `d_win` | 单次、不循环 |
| 委屈 | `e` | 循环指定轮数 |
| 书本金光 | `light` | Track 1 叠加在 IDLE 上，循环指定轮数 |

## 架构

### `PetBehaviorController`

新增一个与 DOM、Electron 和 Spine 解耦的状态机模块。它只接收以下输入：

- `doubleClick()`：角色被双击。
- `animationCompleted({ animationName, trackIndex, playbackId })`：Spine 报告当前播放条目完成一次循环或完成一次非循环播放。
- `tick(deltaSeconds)`：渲染帧推进。
- `setTestMode(enabled)`：切换动画测试独占权。

模块通过回调或返回命令请求播放动画，不直接操作 Spine。每条播放命令都有单调递增的 `playbackId`；适配层把该 ID 与 Spine `TrackEntry` 关联后再回传完成事件。状态替换或进入测试模式时旧 ID 立即失效，因此迟到事件以及同名动画的上一轮事件都不能推进当前状态。构造函数支持注入随机数函数，使概率、轮数和所有边界测试可重复。

### `pet.js` Spine 适配层

`pet.js` 负责：

- 监听 canvas 双击并传给状态机。
- 监听 Spine `complete` 事件，将动画名、Track 和对应 `playbackId` 传入真实完成信号。该信号同时涵盖循环动画的一轮完成与 `d_win` 的单次播放完成。
- 执行状态机的 Track 0 基础动画与 Track 1 金光命令。
- 将每帧 `delta` 传给状态机。
- 在动画应用后叠加眼球骨骼偏移。

状态机是动画所有权的唯一来源。正常模式下不再从设置恢复上次的瞬态动画；启动始终进入 IDLE。

### 主进程全局鼠标采样

主进程使用 Electron `screen.getCursorScreenPoint()` 以约 30 Hz 采样全局鼠标位置，并结合桌宠窗口 bounds 计算桌宠中心。只有桌宠窗口存在且眼神追踪开启时发送坐标，窗口关闭时清理采样定时器。渲染进程在两次采样之间持续使用最后一个有效坐标，不会因尚未收到下一条 IPC 而回正。

预加载脚本只开放明确白名单中的眼神追踪设置和坐标通道。

## 状态机

### 状态

- `IDLE`
- `IDLE_APPRECIATION`
- `GOLDEN_LIGHT`
- `BRUSH_READY`
- `THINKING`
- `TEARING_UP`
- `FRENZY_DRAWING`
- `SIGNING_OFF`
- `BRUSH_APPRECIATION`
- `TEST_MODE`

### IDLE 流程

1. 启动播放 `a` 循环。
2. 每完成 10 个 `a` 循环抽卡一次。
3. 抽中 15% 时播放 `c` 2–5 个循环；结束后回 IDLE，并重新从 0 统计 IDLE 循环。
4. 未抽中时继续 IDLE，下一次在再完成 10 个循环后抽卡。
5. IDLE 双击时：
   - 80% 进入 `BRUSH_READY`，播放 `a_win` 循环，拿笔计时从 0 开始。
   - 20% 进入 `GOLDEN_LIGHT`，保持 `a` 为基础动画，并在 Track 1 播放 `light` 1–2 个循环；完成后回 IDLE，并重置 IDLE 循环统计。

离开 IDLE 进入任何其他状态时都清零 IDLE 循环计数，包括进入拿笔。拿笔流程最终返回 IDLE 时从第 0 轮重新统计。

### 拿笔流程

只有 `BRUSH_READY` 状态累计“总的拿起画笔秒数”。瞬态状态暂停累计且保留已有数值。

累计时间首次跨过 10、20、30 秒阈值时，各抽卡一次：

- 45%：播放思考 `b` 2–10 个循环。
- 25%：播放委屈 `e` 2–7 个循环。
- 30%：不触发动作。

思考结束时另抽一次：

- 5%：进入疯狂绘画。
- 95%：返回拿笔，并从原累计值继续计时。

委屈结束后返回拿笔，并从原累计值继续计时。

`tick(deltaSeconds)` 按时间顺序推进到最近的尚未处理阈值。若该阈值触发瞬态动作，则立即停止处理并丢弃本次 tick 尚未消费的余量，因为从该时刻起拿笔计时本应暂停；若未触发动作，则继续用余量推进到下一个阈值。这样即使出现 `tick(25)` 或 `tick(35)`，也不会并发请求多个 Track 0 动作。30 秒阈值处理完毕后不再消费多余时间。

### 30 秒竞争

跨过 30 秒时先执行该阈值的随机事件判定，再判定退出：

- 抽中思考或委屈：冻结计时，完成整个动作链后再检查累计值。
- 事件结束且累计值仍不低于 30 秒：回 IDLE。
- 抽中不触发：立即回 IDLE。
- 思考结束抽中 5% 疯狂绘画：疯狂绘画入口会先把累计值清零，因此其动作链结束后回拿笔并从 0 秒重新计时。

该顺序保证随机事件优先于 30 秒退出，同时不会让两个事件并发占用 Spine Track 0。

### 疯狂绘画流程

拿笔状态双击立即进入疯狂绘画。进入时：

1. 将拿笔累计秒数清零并暂停。
2. 播放 `d` 3–13 个循环。
3. 自然衔接播放一次非循环 `d_win`。
4. 收笔完成后抽卡：
   - 12%：播放 `c` 2–5 个循环。
   - 88%：直接回拿笔。
5. 欣赏结束或未抽中欣赏时，播放 `a_win` 循环并立即从 0 秒重新计时。

### 输入锁定

仅 `IDLE` 与 `BRUSH_READY` 接受双击。欣赏、金光、思考、委屈、疯狂绘画和收笔期间的双击全部忽略，不排队。

## 眼神鼠标追踪

### 骨骼与叠加顺序

使用现有且未被动画关键帧占用的骨骼：

- `眼_瞳孔_微动`
- `眼_瞳孔L_微动`

初始化时保存两根骨骼的 setup position。每个渲染帧先应用 Spine 动画，再将骨骼位置设置为“setup position + 当前平滑偏移”，禁止在上一帧结果上继续累加。

### 坐标与平滑

1. 以桌宠窗口中心到全局鼠标位置的向量作为视线方向。
2. 精确归一化公式为 `nx = dx / (windowWidth * 1.5)`、`ny = -dy / (windowHeight * 1.5)`；负号将屏幕向下的 Y 轴转换为 Spine 向上的 Y 轴。
3. 若 `sqrt(nx² + ny²) > 1`，将 `nx`、`ny` 同除以该长度，限制到单位圆。宽高分别归一化，使非正方形窗口仍保持各轴一致的视觉行程。
4. 目标骨骼偏移为 `targetX = nx * 24`、`targetY = ny * 16`，单位是 Spine 骨骼本地坐标。
5. 使用半衰期 80ms 的帧率无关指数平滑：`alpha = 1 - 2^(-deltaSeconds / 0.08)`，`current += (target - current) * alpha`。眼神平滑计算只接受 `0 <= deltaSeconds <= 0.25`；更大的渲染间隔按 0.25 秒计算，防止窗口恢复时突跳。

当功能关闭、从未收到有效坐标或骨骼缺失时，目标偏移为零。“暂时没有坐标”仅指本次运行尚无任何有效采样；已有样本会保留到下一条有效样本。关闭开关后眼睛平滑回正；骨骼缺失只警告一次，动画继续正常运行。坐标映射与平滑函数保持为纯函数并单独测试。

## 控制面板

- 侧栏“主面板”改为“桌宠”；英文为 “Mascot”。
- 动画测试按钮中的“画完炫耀”改为“画完欣赏”；英文使用 “Admire Drawing”。
- 在桌宠页背景板中加入一行眼神追踪设置：
  - 文本左对齐。
  - 胶囊开关右对齐。
  - 区域透明，不添加白色卡片、边框或阴影。
  - 使用原生 checkbox 提供键盘切换、焦点环和无障碍语义。
- 开关默认开启，并通过现有 settings JSON 持久化。

### 设置所有权与同步

主进程内的布尔值 `eyeTrackingEnabled` 是单一事实来源，启动时从 settings JSON 读取；缺失或非布尔值一律回退为 `true`。面板和桌宠通过只读调用获取初值。

面板切换时使用有返回值的 IPC 请求。主进程先验证载荷必须为 boolean，再持久化、幂等地启动或停止采样器，并广播最终有效值；面板以返回值校准开关，桌宠以广播值更新目标行为。重复设置相同值不得创建第二个定时器。桌宠窗口重建时按当前主进程值恢复采样；窗口正在销毁或已销毁时不发送 IPC。非法载荷被拒绝且不改变当前设置。

## 动画测试模式

测试模式开启时：

- 自动状态机使所有自动播放 `playbackId` 失效，清空 Track 0、Track 1 及 Spine 动画队列，再进入 `TEST_MODE`，停止计时、循环抽卡和双击响应。
- 手动动画按钮拥有 Track 0；金光测试开关继续拥有 Track 1。

测试模式关闭时：

- 清除测试金光 Track。
- 重置自动状态机并从 IDLE 开始。
- 不恢复测试期间选择的动画。

## 错误处理与生命周期

- 状态机忽略与当前状态、Track 或当前 `playbackId` 不匹配的迟到动画完成事件。
- 窗口销毁后停止全局鼠标采样，避免定时器和 IPC 泄漏。
- 非法或非有限 `delta`、坐标输入不推进计时，也不污染骨骼位置。
- Spine 眼部骨骼缺失时关闭本次运行的追踪适配，不影响其余功能。
- 设置加载失败时使用安全默认值：眼神追踪开启、测试模式关闭、IDLE 启动。

## 调试时序日志

状态机接受可注入的 logger，并默认向控制台输出低频、结构化的时序日志。每条记录使用固定前缀 `[pet-behavior]`，包含单调递增的 `seq`、单调时钟时间、事件名和当前状态。按事件补充以下字段：

- 双击：是否接收；忽略时记录锁定状态。
- 状态切换：`from`、`to` 和触发原因。
- 抽卡：阈值或来源、原始 `roll`、结果和抽中的循环数。
- 动画：动画名、Track、`playbackId`、循环进度和目标轮数。
- 拿笔计时：跨过的 10/20/30 秒阈值，以及暂停、继续、清零原因。
- 竞争保护：迟到或不匹配完成事件被拒绝的原因。
- 测试模式：接管与释放，以及被作废的自动播放 ID。

不记录逐帧 `tick` 或逐帧眼球位置，避免淹没时序信息。日志不得包含路径、设置文件内容或其他非行为数据。测试使用收集型 logger 直接断言关键事件顺序，不依赖拦截全局 console。

## 测试策略

使用 Node 内置测试运行器测试纯状态机，不新增测试依赖。随机数以固定序列注入，覆盖：

- IDLE 每 10 轮的 15% 命中和未命中。
- IDLE 双击的 80% 拿笔与 20% 金光分支。
- 所有随机循环范围的上下边界。
- 拿笔 10、20、30 秒阈值以及 45% / 25% / 30% 分支。
- 瞬态期间计时暂停、双击忽略且不排队。
- 思考结束的 5% 疯狂绘画分支。
- 疯狂绘画入口清零、3–13 轮、单次收笔、12% 欣赏和正确返回目标。
- 30 秒随机事件优先以及事件结束后的二次判定。
- 测试模式进入、退出和 IDLE 重置。
- 同名旧播放条目的迟到完成事件，以及 `d_win` 单次完成事件。
- `tick(25)`、`tick(35)` 的按序阈值处理与余量丢弃。
- 从所有瞬态状态进入测试模式时，播放 ID 失效、双 Track 清空且旧事件无效。
- 离开 IDLE 前已有 9 轮时进入拿笔，再返回 IDLE 后循环计数从 0 开始。
- 眼神映射的各轴归一化、单位圆限幅、Y 轴翻转、最大偏移、不同帧率下的等效平滑、非法输入和关闭后的平滑回正。
- 眼神设置的默认值、布尔校验、重复切换幂等、桌宠窗口重建和销毁期间不发送。
- 结构化日志的序号、状态转换、抽卡、计时、动画完成、忽略双击和迟到事件顺序。

随机数函数约定返回 `[0, 1)`。概率区间固定为：IDLE 欣赏 `r < 0.15`；IDLE 双击 `r < 0.80` 进入拿笔，否则金光；拿笔检查 `r < 0.45` 思考、`0.45 <= r < 0.70` 委屈、否则不触发；思考结束 `r < 0.05` 进入疯狂绘画；收笔结束 `r < 0.12` 进入欣赏。整数范围使用 `min + floor(r * (max - min + 1))`，上下界均可取。每次分支先消耗一次随机数，仅在进入需要随机轮数的状态后再消耗一次轮数随机数。

集成验证包括：

- JavaScript 语法检查和完整单元测试。
- 启动 Electron，确认无渲染进程错误。
- 检查桌宠页透明设置行、胶囊开关、国际化文案和持久化。
- 实际移动全局鼠标，确认双眼平滑、限幅、回正且不影响拖拽和透明点击穿透。
- 实际双击桌宠，确认输入锁定、基础动画与金光 Track 不冲突。

## 不在本次范围

- 不修改 Spine JSON、atlas 或 PNG 资产。
- 不新增第三方依赖。
- 不改变桌宠尺寸、拖拽、透明点击穿透或托盘行为。
- 不实现可配置概率、轮数或调试状态可视化。
