# 眼神鼠标追踪与桌宠动画行为设计

## 目标

为 Electron 桌宠加入默认开启、可持久化的全屏眼神鼠标追踪，并用可测试的独立状态机实现双击随机动画、循环计数、拿笔计时和竞争优先级。控制面板中的“主面板”改名为“桌宠”，眼神追踪开关直接安插在内容背景上，不增加卡片底色。

## 已确认规则

- IDLE 每完成 10 个循环抽卡一次，以 15% 概率进入“画完欣赏”。
- 拿笔状态每累计 10 秒抽卡：思考 45%、委屈 25%、不触发 30%。
- 所有瞬态动作期间忽略双击，当前动作链不可被截断。
- 眼神追踪默认开启、全屏生效、设置持久化；关闭后平滑回正。
- 疯狂绘画后的 `d_win` 是一次非循环收笔动画。
- 动画测试模式暂停自动状态机并独占动画播放；退出测试模式时回到 IDLE。

## 动画映射

| 语义 | Spine 动画 | 播放方式 |
|---|---|---|
| IDLE | `a` | 循环 |
| 拿起画笔 | `a_win` | 循环 |
| 思考 | `b` | 循环指定轮数 |
| 画完欣赏 | `c` | 循环指定轮数 |
| 疯狂画画 | `d` | 循环指定轮数 |
| 画完收笔 | `d_win` | 单次、不循环 |
| 委屈 | `e` | 循环指定轮数 |
| 书本金光 | `light` | Track 1 叠加在 IDLE 上，循环指定轮数 |

## 架构

### `PetBehaviorController`

新增一个与 DOM、Electron 和 Spine 解耦的状态机模块。它只接收以下输入：

- `doubleClick()`：角色被双击。
- `animationLoopCompleted(animationName)`：Spine 报告一次动画循环完成。
- `tick(deltaSeconds)`：渲染帧推进。
- `setTestMode(enabled)`：切换动画测试独占权。

模块通过回调或返回命令请求播放动画，不直接操作 Spine。构造函数支持注入随机数函数，使概率、轮数和所有边界测试可重复。

### `pet.js` Spine 适配层

`pet.js` 负责：

- 监听 canvas 双击并传给状态机。
- 监听 Spine `complete` 事件并传入真实循环完成信号。
- 执行状态机的 Track 0 基础动画与 Track 1 金光命令。
- 将每帧 `delta` 传给状态机。
- 在动画应用后叠加眼球骨骼偏移。

状态机是动画所有权的唯一来源。正常模式下不再从设置恢复上次的瞬态动画；启动始终进入 IDLE。

### 主进程全局鼠标采样

主进程使用 Electron `screen.getCursorScreenPoint()` 以约 30 Hz 采样全局鼠标位置，并结合桌宠窗口 bounds 计算桌宠中心。只有桌宠窗口存在且眼神追踪开启时发送坐标，窗口关闭时清理采样定时器。

预加载脚本只开放明确白名单中的眼神追踪设置和坐标通道。

## 状态机

### 状态

- `IDLE`
- `IDLE_APPRECIATION`
- `GOLDEN_LIGHT`
- `BRUSH_READY`
- `THINKING`
- `TEARING_UP`
- `FRENZY_DRAWING`
- `SIGNING_OFF`
- `BRUSH_APPRECIATION`
- `TEST_MODE`

### IDLE 流程

1. 启动播放 `a` 循环。
2. 每完成 10 个 `a` 循环抽卡一次。
3. 抽中 15% 时播放 `c` 2–5 个循环；结束后回 IDLE，并重新从 0 统计 IDLE 循环。
4. 未抽中时继续 IDLE，下一次在再完成 10 个循环后抽卡。
5. IDLE 双击时：
   - 80% 进入 `BRUSH_READY`，播放 `a_win` 循环，拿笔计时从 0 开始。
   - 20% 进入 `GOLDEN_LIGHT`，保持 `a` 为基础动画，并在 Track 1 播放 `light` 1–2 个循环；完成后回 IDLE，并重置 IDLE 循环统计。

### 拿笔流程

只有 `BRUSH_READY` 状态累计“总的拿起画笔秒数”。瞬态状态暂停累计且保留已有数值。

累计时间首次跨过 10、20、30 秒阈值时，各抽卡一次：

- 45%：播放思考 `b` 2–10 个循环。
- 25%：播放委屈 `e` 2–7 个循环。
- 30%：不触发动作。

思考结束时另抽一次：

- 5%：进入疯狂绘画。
- 95%：返回拿笔，并从原累计值继续计时。

委屈结束后返回拿笔，并从原累计值继续计时。

### 30 秒竞争

跨过 30 秒时先执行该阈值的随机事件判定，再判定退出：

- 抽中思考或委屈：冻结计时，完成整个动作链后再检查累计值。
- 事件结束且累计值仍不低于 30 秒：回 IDLE。
- 抽中不触发：立即回 IDLE。
- 思考结束抽中 5% 疯狂绘画：疯狂绘画入口会先把累计值清零，因此其动作链结束后回拿笔并从 0 秒重新计时。

该顺序保证随机事件优先于 30 秒退出，同时不会让两个事件并发占用 Spine Track 0。

### 疯狂绘画流程

拿笔状态双击立即进入疯狂绘画。进入时：

1. 将拿笔累计秒数清零并暂停。
2. 播放 `d` 3–13 个循环。
3. 自然衔接播放一次非循环 `d_win`。
4. 收笔完成后抽卡：
   - 12%：播放 `c` 2–5 个循环。
   - 88%：直接回拿笔。
5. 欣赏结束或未抽中欣赏时，播放 `a_win` 循环并立即从 0 秒重新计时。

### 输入锁定

仅 `IDLE` 与 `BRUSH_READY` 接受双击。欣赏、金光、思考、委屈、疯狂绘画和收笔期间的双击全部忽略，不排队。

## 眼神鼠标追踪

### 骨骼与叠加顺序

使用现有且未被动画关键帧占用的骨骼：

- `眼_瞳孔_微动`
- `眼_瞳孔L_微动`

初始化时保存两根骨骼的 setup position。每个渲染帧先应用 Spine 动画，再将骨骼位置设置为“setup position + 当前平滑偏移”，禁止在上一帧结果上继续累加。

### 坐标与平滑

1. 以桌宠窗口中心到全局鼠标位置的向量作为视线方向。
2. 按窗口尺度归一化并限制为单位圆内的向量。
3. 将屏幕向下的 Y 轴转换为 Spine 向上的 Y 轴。
4. 应用保守的水平、垂直最大偏移。
5. 使用与帧率无关的指数平滑追赶目标。

当功能关闭、暂时没有坐标或骨骼缺失时，目标偏移为零。关闭开关后眼睛平滑回正；骨骼缺失只警告一次，动画继续正常运行。

## 控制面板

- 侧栏“主面板”改为“桌宠”；英文为 “Mascot”。
- 动画测试按钮中的“画完炫耀”改为“画完欣赏”；英文使用 “Admire Drawing”。
- 在桌宠页背景板中加入一行眼神追踪设置：
  - 文本左对齐。
  - 胶囊开关右对齐。
  - 区域透明，不添加白色卡片、边框或阴影。
  - 使用原生 checkbox 提供键盘切换、焦点环和无障碍语义。
- 开关默认开启，并通过现有 settings JSON 持久化。

## 动画测试模式

测试模式开启时：

- 自动状态机进入 `TEST_MODE` 并停止计时、循环抽卡和双击响应。
- 手动动画按钮拥有 Track 0；金光测试开关继续拥有 Track 1。

测试模式关闭时：

- 清除测试金光 Track。
- 重置自动状态机并从 IDLE 开始。
- 不恢复测试期间选择的动画。

## 错误处理与生命周期

- 状态机忽略与当前状态不匹配的迟到动画完成事件。
- 窗口销毁后停止全局鼠标采样，避免定时器和 IPC 泄漏。
- 非法或非有限 `delta`、坐标输入不推进计时，也不污染骨骼位置。
- Spine 眼部骨骼缺失时关闭本次运行的追踪适配，不影响其余功能。
- 设置加载失败时使用安全默认值：眼神追踪开启、测试模式关闭、IDLE 启动。

## 测试策略

使用 Node 内置测试运行器测试纯状态机，不新增测试依赖。随机数以固定序列注入，覆盖：

- IDLE 每 10 轮的 15% 命中和未命中。
- IDLE 双击的 80% 拿笔与 20% 金光分支。
- 所有随机循环范围的上下边界。
- 拿笔 10、20、30 秒阈值以及 45% / 25% / 30% 分支。
- 瞬态期间计时暂停、双击忽略且不排队。
- 思考结束的 5% 疯狂绘画分支。
- 疯狂绘画入口清零、3–13 轮、单次收笔、12% 欣赏和正确返回目标。
- 30 秒随机事件优先以及事件结束后的二次判定。
- 测试模式进入、退出和 IDLE 重置。

集成验证包括：

- JavaScript 语法检查和完整单元测试。
- 启动 Electron，确认无渲染进程错误。
- 检查桌宠页透明设置行、胶囊开关、国际化文案和持久化。
- 实际移动全局鼠标，确认双眼平滑、限幅、回正且不影响拖拽和透明点击穿透。
- 实际双击桌宠，确认输入锁定、基础动画与金光 Track 不冲突。

## 不在本次范围

- 不修改 Spine JSON、atlas 或 PNG 资产。
- 不新增第三方依赖。
- 不改变桌宠尺寸、拖拽、透明点击穿透或托盘行为。
- 不实现可配置概率、轮数或调试状态可视化。
