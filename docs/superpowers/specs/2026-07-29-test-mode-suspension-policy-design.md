# 测试模式暂停协议设计

## 目标与范围

动画控制测试开启时，所有会干扰测试的功能必须停止运行，并在面板中灰化且不可操作。暂停不得改写用户的持久化开关值；退出测试后按原配置恢复。

当前暂停自动动画状态机、抽卡、计时、桌宠双击交互和眼神鼠标追踪。尺寸、语言、窗口置顶及手动动画测试控件保持可用。

## 面板声明协议

- 需要停用的设置区域声明 `data-test-mode-policy="suspend"`，并以 `data-test-mode-feature` 标识对应运行功能。
- 面板统一查询该声明，不维护控件 ID 白名单。
- 开启时设置 `inert`、`aria-disabled="true"` 和 `.is-test-suspended`；退出时统一移除。
- `inert` 不覆写后代控件原有的 `disabled` 值，避免异步请求和测试模式互相覆盖。
- 灰化样式使用声明选择器；未来新增暂停项只需添加声明。

当前仅眼神追踪行声明 `data-test-mode-feature="eye-tracking"`。测试模式开关及手动动画控件不得声明暂停。

## 运行时暂停闸门

主进程是测试模式有效状态的事实来源。面板通过有返回值的 `get-test-mode` 与 `set-test-mode` IPC 读取和切换状态，请求完成前禁用测试模式开关；失败时回滚显示，不开放手动测试控件，也不保存为已开启。

主进程先暂停或恢复眼神采样服务，再把状态发送给桌宠渲染端，最后返回已确认状态。眼神采样服务的 `_syncSampler()` 和 `_sample()` 都必须检查暂停状态，使已经排队的定时回调也无法发送样本。测试模式持久化值用于主进程启动状态，避免窗口加载时先启动采样。

桌宠渲染端提供同步功能闸门。功能以唯一名称注册 `suspend` 和 `resume` 回调：

- 状态切换对所有注册功能执行一次对应回调，重复设置幂等。
- 测试模式期间注册的新功能立即暂停。
- 回调必须同步完成。闸门继续处理所有功能并汇总异常；任何回调失败都使本次转换失败并回滚已处理功能，不能把部分暂停表示为成功。
- 注册返回注销函数；拒绝同名重复注册。

自动动画状态机和眼神追踪目标计算接入该闸门。闸门的单一有效状态同时控制行为控制器、双击授权、手动动画授权及眼神追踪暂停，不保存用户设置。抽卡、计时和双击属于自动动画功能内部职责，不单独注册。

## 眼神追踪

- 开启测试后主进程停止采样，渲染端以 `desiredEnabled && !testSuspended` 计算有效状态，使既有最后样本失效，并沿用现有插值平滑回中。
- `eyeTrackingEnabled` 及磁盘设置保持原值。
- 退出测试后根据当前 desired 设置重新计算，不保存进入测试时的快照。

## 自动动画

- 现有 `TEST_MODE` 状态继续清空轨道、停止抽卡与计时并拒绝双击。
- 统一闸门负责调用行为控制器；手动动画 IPC 仍仅在测试模式下接受。
- 退出测试模式后按既有约定回到 `IDLE`。

## 日志与测试

- 闸门记录状态变化、功能名、暂停或恢复结果及异常，沿用 `[pet-behavior]` 诊断通道。
- 单元测试覆盖暂停、恢复、幂等、开启期间注册、注销、失败回滚及采样器排队回调。
- 面板合同测试覆盖声明、`inert`、ARIA 和统一灰化样式。
- 桌宠合同测试覆盖眼神追踪同时受用户设置与测试暂停状态约束。
- Electron QA 验证眼神追踪灰化且不可操作，非暂停设置及手动测试控件保持可用，退出后恢复。

## 不在范围

- 不改变动画概率、循环次数或计时规则。
- 不停用窗口拖动、右键菜单、尺寸、语言或窗口置顶。
- 不迁移测试模式持久化方式。
